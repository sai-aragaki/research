検索するのは、
文字列ではなく
「もの」になった。

2012年5月、Google の検索部門を率いていた Amit Singhal は、ブログに「Introducing the Knowledge Graph: things, not strings」という記事を書いた。それまでの検索は、入力された文字列と同じ文字列を含むページを探していた。「タージ・マハル」と入れれば、インドの霊廟の話も、同じ名前のミュージシャンの話も、同じ文字列として並ぶ。新しい仕組みでは、検索エンジンが「タージ・マハル」という名前の背後にある「もの」を区別し、それが建物なのか人なのか、どこにあり、誰と関係しているのかを知っている。発表の時点で、そこには5億を超える「もの」と、それらについての35億を超える事実と関係が入っていた。前回は、検索の良し悪しのほとんどが検索窓の外で決まると見た。ファセットにも同義語にもベストベットにも、その下に、中身に付けられた属性と、言葉どうしの関係が要る。この回は、その層を扱う。メタデータ、タクソノミー、オントロジー、ナレッジグラフ。⑤で見た図書館の目録とシソーラスが、Web の上でどう姿を変えてきたのかをたどる。

01 ── Things

一つの言葉が、いくつものものを指す

From strings to things

⑥で、同じものを人が違う言葉で呼ぶ問題を見た。二人が同じ言葉を選ぶ確率は2割に満たなかった。タージ・マハルの例は、その裏返しだ。一つの言葉が、いくつもの違うものを指す。「Apple」は果物でも会社でもあり、「ジャガー」は動物でも車でもある。

文字列を照らし合わせるだけの仕組みは、どちらの問題も解けない。違う言葉で書かれた同じものは見つけられず、同じ言葉で書かれた違うものは区別できない。解くには、言葉の向こうに「もの」を一つずつ置き、その「もの」に、言葉と属性と関係を結びつけておく必要がある。

この「言葉の向こうのもの」をどこまで細かく、どこまで機械に分かる形で書くか。その程度の違いが、この回に出てくる道具の違いになる。

02 ── Third Order

本から切り離された、本についての情報

Metadata and the three orders of order

2007年、David Weinberger は『Everything Is Miscellaneous』で、ものを整理するやり方を三つの段階に分けた。

第一の秩序
First order

もの自体を並べる。本を棚に、皿を食器棚に。一つのものは一か所にしか置けない。

第二の秩序
Second order

ものについての情報を、ものから切り離して並べる。図書館のカード目録。同じ本のカードを、著者順と書名順と主題順の三か所に置ける。

第三の秩序
Third order

ものも、ものについての情報もデジタルになる。いくつの場所にも置け、その場で何通りにも並べ替えられる。

第二の秩序のカードに書かれていたものを、いまは「メタデータ」と呼ぶ。データについてのデータ、つまり、ある中身を説明するための情報だ。⑤で見たデューイの相対配架とファセットの話は、第一の秩序の制約（一か所にしか置けない）から、第二、第三の秩序へ移っていく話だったと言える。

15の項目で、Web のあらゆる資料を記述する

Web のためのメタデータを最初にまとめようとしたのは、図書館の人たちだった。1994年の秋、シカゴの Web 会議の会場で、生まれたばかりの Web ではもう資料を探すのが難しい、という立ち話が交わされた。それをきっかけに、翌1995年3月、図書館の目録サービスを運営する OCLC と、ブラウザ Mosaic を生んだ NCSA が、オハイオ州ダブリンで会議を開いた。

そこでまとめられた13の項目に、まもなく2つが足され、15の項目からなる「ダブリン・コア」ができた。タイトル、作成者、主題、説明、発行者、日付、種類、形式、識別子、言語、権利など、どんな種類の資料にも使える、ごく基本的な項目だけを選んだものだ。のちに ISO 15836 として国際規格になっている。

米国の情報標準化機構（NISO）の入門書は、メタデータを役割で三つに分けている。中身を見つけ、何であるかを知るための「記述」メタデータ（タイトル、作者、キーワード）。部分どうしのつながりを表す「構造」メタデータ（ページの順序、章立て）。そして、管理のための「管理」メタデータ（作成日、ファイル形式、利用の権利）。ユーザーの目に触れるのは主に記述メタデータだが、⑧で見たファセットや並べ替えが働くかどうかは、この三つ全部がきちんと付いているかに左右される。

03 ── Ladder

言葉を管理する道具には、段階がある

From term lists to ontologies

メタデータの中でも、主題やカテゴリーのように「言葉」で書く項目は、書く人によって表記がばらつく。それをそろえるための道具が、⑤で見た統制語彙だ。タクソノミーの実務家 Heather Hedden は『The Accidental Taxonomist』で、こうした道具をまとめて扱い、語どうしの関係をどれだけ細かく書くかで違いを整理している。

語どうしの関係が増えていく階段
Hedden『The Accidental Taxonomist』の整理と ANSI/NISO Z39.19 をもとに筆者が作図
語のリスト使ってよい語を並べる例：都道府県の一覧
同義語リング同じ意味の語を束ねる例：チャリ＝自転車＝サイクル
典拠ファイル束ねた中から正式な形を一つ決める例：人名・社名の正式表記
タクソノミー語を上位・下位の階層に並べる例：家具 › 椅子 › 事務椅子
シソーラス階層に、等価と連想の関係を加える例：⑤の USE／UF、BT／NT、RT
オントロジー関係そのものに種類と意味を持たせる例：「監督した」「出演した」「所在地は」

上に行くほど、語どうしの関係がたくさん書けるようになる。その分、作るのも保つのも手間がかかる。どの段階まで必要かは、中身の量と、その構造に何をさせたいかで決まる。ECサイトの絞り込みならタクソノミーと同義語で足りることが多い。辞書や百科事典のように「もの」どうしの関係を機械にたどらせたいなら、オントロジーまで要る。

「タクソノミー」という言葉の広がり

Hedden は、タクソノミーという言葉がこの20年ほどで意味を広げ、いまでは情報の整理一般を指すように使われていると指摘している。実務の会話で「タクソノミーを作る」と言うとき、それが階層だけを指すのか、同義語やシソーラスまで含むのかは、最初に確かめておいたほうがいい。

04 ── Ontology

何があり、どう関係するかを書き下す

Ontologies and triples

オントロジーは、もともと哲学で「何が存在するか」を論じる分野の名前だった。1993年、スタンフォード大学の Thomas Gruber は、人工知能の研究者どうしが知識を共有するための文脈で、この言葉に工学的な定義を与えた。オントロジーとは、概念化の明示的な仕様である。ある分野でどんな概念がありえて、それらがどんな関係を持ちうるかを、はっきり書き下したもの、という意味だ。この論文は、掲載誌の歴史で最も多く引用された論文になっている。

①で見た Dan Klyn の三つの歯車を思い出してほしい。意味（オントロジー）、構造（タクソノミー）、流れ（コレオグラフィ）。Klyn がオントロジーを「意味」の歯車に置いたのは、この意味での使い方だ。言葉が何を指していて、指されたものどうしがどうつながっているのか。

主語、述語、目的語

タクソノミーとの違いは、関係の種類にある。タクソノミーの関係は、基本的に「上位と下位」の一種類しかない。オントロジーでは、関係そのものに名前を付けられる。

「もの」と、名前の付いた関係
筆者による例。矢印一本が「主語・述語・目的語」の一組（トリプル）に当たる

「千と千尋の神隠し」「監督」「宮崎駿」。主語、述語、目的語の三つ組（トリプル）で一つの事実を書き、それをたくさんつなげると網の目になる。この網の目を、大規模に、実際の「もの」について作ったものを、いまはナレッジグラフと呼ぶ。Google のナレッジグラフの35億の事実は、こうした三つ組の集まりだ。

関係に名前があると、機械が網の目をたどれる。「宮崎駿が監督した、2000年以降の映画」は、文字列の照合では答えられないが、三つ組の網の目なら、監督の矢印と公開年の矢印をたどるだけで答えが出る。

05 ── Tags

利用者が付ける分類もある

Folksonomies and the case against ontology

ここまでの道具は、どれも作り手の側が言葉を決めるものだった。2000年代半ば、逆向きの動きが Web に現れた。ソーシャルブックマークの del.icio.us や、写真共有の Flickr で、利用者が自分の保存したものに、好きな言葉の「タグ」を自由に付けられるようになったのだ。

2004年、情報設計者の Thomas Vander Wal は、このやり方を「フォークソノミー」と呼んだ。folk（人々）と taxonomy を合わせた言葉だが、彼自身は、できあがるものはタクソノミーではない、と付け加えている。階層も、統制も、正式な形もない。たくさんの人が付けた言葉が、ただ積み重なっていく。

翌2005年、作家の Clay Shirky は「Ontology is Overrated（オントロジーは過大評価されている）」という講演で、Web は分類の歴史の延長ではなく、そこからの断絶だと論じた。棚の制約がない世界では、あらかじめ決めた分類より、人々が付けるタグのほうが、変わり続ける中身と関心に追いつける、という主張だ。

タグの強さと弱さ

タグの強みは、⑤で見た「利用者的根拠」をそのまま形にしていることだ。作り手が思いつかない言葉、新しく生まれた言葉が、すぐに分類に入ってくる。弱みは、⑥の語彙の問題がそのまま残ることだ。「猫」「ねこ」「cat」「にゃんこ」が別々のタグとして並び、綴りの間違いも混ざる。

実務でよく使われるのは、両方を組み合わせるやり方だ。利用者のタグを集め、よく使われるものを統制語彙の同義語として取り込み、正式な語に結びつける。タグは、統制語彙を育てるための、利用者の言葉の観測装置として働く。⑧の検索ログと同じ役割だ。

06 ── Web

機械にも読める意味を、Web に載せる

The Semantic Web, SKOS, and Schema.org

2001年5月、Web の考案者 Tim Berners-Lee は、James Hendler、Ora Lassila と共に『Scientific American』誌に「The Semantic Web」という記事を書いた。今の Web は人が読むための文書の網だが、そこに書かれた情報に、はっきりした意味を与えれば、コンピュータも内容を理解して、人と一緒に働けるようになる、という構想だった。

構想の全体は、思い描かれたほどには実現しなかった。だが、その道具立ての一部は、静かに広く使われるようになっている。

シソーラスを、Web の言葉で書く

2009年、Web の標準化団体 W3C は、シソーラスやタクソノミーを Web 上で共有するための規格「SKOS」を勧告にした。中身を見ると、⑤で見たシソーラスの関係が、そのまま Web の語彙に置き換えられているのが分かる。

シソーラス（⑤）SKOS意味
優先語prefLabelその概念の正式な呼び名
UF（非優先語）altLabel別の呼び名、同義語、表記ゆれ
BT／NTbroader／narrower上位の概念と下位の概念
RTrelated上下ではない関連

1世紀かけて図書館が磨いてきた言葉の管理の作法は、Web の規格の中にほぼそのまま入っている。

検索エンジンが読むための語彙

2011年6月には、Google、Microsoft の Bing、Yahoo! が共同で「Schema.org」を立ち上げ、同じ年の秋にロシアの Yandex も加わった。ページの中の情報が、商品なのか、レシピなのか、イベントなのか、その価格や日時や場所はどれなのかを、検索エンジンが読める形で書き込むための共通の語彙だ。検索結果に星の評価や開催日が表示されるのは、この記述が読まれているからだ。2015年に Google が100億ページの標本を調べたところ、31.3%のページが Schema.org の記述を持っていた。前年の22%から増えている。

セマンティック Web の大きな構想が掲げた「機械が意味を理解する Web」は、こうして、検索エンジンとサイトの作り手のあいだの実利的な約束事という形で、部分的に実現した。

07 ── BBC

画面より先に、扱う世界を設計する

Domain modeling at the BBC

こうした道具を、メディアのサイト全体の設計に使った例として、よく引かれるのが英国の BBC だ。

2008年、BBC は自然と料理のサイトを作り直すとき、ページの構成から考えるのをやめ、まず扱う世界そのもの（ドメイン）をモデルにした。自然のサイトなら、動物の種、その生息地、その行動、それが登場する番組。それぞれを「もの」として識別子を与え、関係を結び、野生生物のオントロジーとして公開した。ページは、このモデルの上に作られた。

2010年のサッカー・ワールドカップのサイトでは、この考え方をさらに進めた。記者が書いた記事に、出てくる選手、チーム、試合といった「もの」をタグとして付ける。すると、オントロジーの関係をたどって、その選手が所属するチーム、そのチームが出る試合、そのグループのページにも、記事が自動的に並ぶ。人が一つずつページを編集する代わりに、意味の層からページが組み立てられる。BBC はこの仕組みを、翌2011年にスポーツのサイト全体へ、2012年にはロンドン五輪のサイトへ広げた。

Insight 01

ページは、意味の層の「見え方」の一つにすぎない

ドメインのモデルを先に作り、ページはそのモデルの上に生成する。そうすると、新しいページの種類（選手別、試合別）を足すのは、モデルの関係を一本たどる見え方を足すことになる。⑥で見たデータベース型の構造を、サイト全体に広げた形だ。

自動生成されたページ数について

BBC のワールドカップのサイトで自動的に作られたページの数は、関わった技術会社の紹介では800以上とされているが、BBC 自身の数字は今回確認できなかった。

08 ── Layer

意味の層は、人と機械の両方に効く

Structure apart from screens

この回で見てきたことは、一つの方向にまとまる。構造を、画面から切り離すことだ。

サイトマップやメニューのような画面の構造は、特定の画面の大きさ、特定のサイトの見せ方に縛られている。スマホで表示を変えるたび、アプリを作るたび、音声のアシスタントに対応するたびに、作り直しになる。その手前に、「何があり、どう呼ばれ、どう関係しているか」という意味の層を持っておけば、画面はその層の見え方の一つになる。同じ層から、Web のメニューも、アプリの一覧も、検索のファセットも、外部の検索エンジンへの Schema.org の記述も作れる。

そしていま、この層を読む新しい読み手が現れている。大規模言語モデルを使った AI のアシスタントだ。AI に社内の文書やサイトの中身を答えさせる仕組みは、文書をそのまま渡すだけでなく、「もの」と関係の網の目（ナレッジグラフ）を手がかりにして関連する情報を探すやり方へと広がりつつある。⑥の語彙の問題も、⑧の再現率の問題も、相手が AI になったからといって消えるわけではない。意味の層が整っているかどうかが、AI がどれだけ正しく答えられるかにも効いてくる。

AI とナレッジグラフについて

ナレッジグラフを AI の回答に使うやり方（GraphRAG などと呼ばれる）がどこまで実務に広まっているかは、今回確かめていない。⑫で改めて調べる。

Insight 02

情報設計の成果物は、画面の外にも残る

ワイヤーフレームは画面が変われば古びるが、よく作られた語彙とドメインのモデルは、画面が何度変わっても使い続けられる。情報設計者がいちばん長く効く仕事を残せるのは、この層だ。

09 ── Carry

この回から、次の回へ持っていくもの

What this chapter hands to the rest of the series

Insight 03

言葉の向こうに「もの」を置く

同じものを違う言葉で呼ぶ問題と、同じ言葉が違うものを指す問題は、文字列の照合では解けない。「もの」に識別子を与え、言葉と属性と関係を結びつける。

Insight 04

必要な段階まで登ればいい

語のリスト、同義語、典拠、タクソノミー、シソーラス、オントロジー。上に行くほど関係が増え、手間も増える。中身の量と、構造に何をさせたいかで、どこまで登るかを決める。

Insight 05

作り手の語彙と、利用者のタグを組み合わせる

統制語彙は一貫性を、タグは新しい言葉を持ち込む。タグや検索ログを観測装置にして、統制語彙を育てる。

次回：構造を、目に見える形にする

この回で、構造は画面から切り離された意味の層になった。では、その構造を人に見せるときはどうするのか。次回⑩は、①の Wurman の出発点に戻り、情報デザインと図解を扱う。Otto Neurath の絵文字言語アイソタイプ、Jacques Bertin の視覚変数、Edward Tufte のデータ・インク。②で見た知覚と注意の研究が、ここで「見せる」側の技法として戻ってくる。
